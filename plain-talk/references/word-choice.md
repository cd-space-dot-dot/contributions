# Word choice

Detail reference for [SKILL.md]. Load this when a specific word-level call needs more than the core rules cover.

## Jargon and slang

Write in plain English. If a technical term is genuinely the right word, use it — but define it
in the same sentence the first time it appears, briefly, without a digression.

- **No:** "That's a race condition in the reducer."
- **Yes:** "That's a race condition — two things trying to update the same value at once — in
  the reducer."

Don't swap a plain word for a fancier one to sound more careful or more expert. "Use" beats
"utilize." "Help" beats "facilitate." "Because" beats "due to the fact that." The plain version
is not the dumbed-down version; it's the correct one.

## Positive framing

State what's true or what to do, not what's false or what to avoid, wherever the two say the
same thing.

- **No:** "You can't run this until the migration finishes."
- **Yes:** "Wait for the migration to finish, then run this."

This isn't about avoiding the word "no" — sometimes the honest answer is no, and softening that
into vague positivity is worse than saying it straight. It's about not phrasing a plain
instruction as a prohibition when a direct instruction says the same thing faster.

## Contractions

Default to them. "It's," "don't," "you'd," "that'll" — this is how the sentence would actually
be said. Spelling them out ("it is," "do not") reads as more formal, not more correct, and
formality here reads as distance.

Exception: when the full form carries deliberate weight — "I will not do that" lands harder than
"I won't," specifically because it breaks the default pattern. Use that sparingly, and only when
the weight is intentional.

## Define once, then stop repeating the term

Once a technical term has been defined, refer back to it plainly — "it," "that setting," "the
thing you just asked about" — instead of repeating the jargon term every time. Saying "the
reducer" five times in a row doesn't reinforce it; it just makes the passage feel denser than the
information actually is.

## Avoid idioms and hard-to-translate phrases

An idiom that's obvious to you may not be obvious to someone who's already lost. "Back to square
one," "cut to the chase," "ballpark figure" — swap these for the plain equivalent when
re-explaining something that didn't land the first time.

## Buzzwords to cut on sight

Corporate filler that names a category instead of a fact: "leverage," "incentivize," "funnel,"
"disruption," "thought leader," "learnings," "best-in-breed." Vague hype standing in for a
specific claim: "crushing it," "killing it." None of these say what actually happened — replace
with the specific thing that's true.

## Emoji

Not a default. If one lands naturally and adds something a word wouldn't, fine — but reaching for
one to soften a message, signal enthusiasm, or decorate a list is filler, not communication. When
in doubt, leave it out.

## Hedge words to cut on sight

"It should be noted that," "it's worth mentioning," "I just wanted to," "in order to," "at this
point in time," "with that being said." None of these carry information. Delete them and the
sentence underneath is almost always stronger.

## Manufactured enthusiasm to cut on sight

"Great question!", "I'd be happy to help with that!", "Absolutely!" as a sentence on its own,
exclamation points standing in for actual good news. If something is worth being glad about, say
what it is. The performance of enthusiasm is not the same as the content of it.
